# popMind 剪贴板重构实施文档（对标 Paste + 智能搜索）

> 状态：方案已确认，并行开发中（集成分支 `feat/clipboard-paste`）
> 日期：2026-09-29
> 范围：macOS。Windows / iCloud 同步 / 团队共享 Pinboard 不在本次范围。

---

## 1. 目标

分两大阶段：

**阶段 A：复刻 Paste**

1. 交互体验和 [Paste](https://pasteapp.io/) 一致：全局快捷键从屏幕底部滑出卡片条，键盘优先，回车直接粘贴到当前应用
2. 采集稳定：不丢、不重复、不回环、不记录密码
3. 支持文本、富文本、链接、图片、文件、颜色六类内容，粘贴时尽量还原原始格式
4. Pinboard（收藏夹）、Quick Look 预览、纯文本粘贴、数字快捷粘贴、Paste Stack（连续粘贴）、重命名 / 编辑、拖拽、多选
5. 历史保留策略、忽略应用、暂停记录

**阶段 B：智能搜索**

1. 基础搜索（本地，永远可用）：文字 + 图片（图片用 macOS Vision OCR 转文字）+ 来源应用 + 类型 + 时间筛选，中文友好，毫秒级
2. AI 搜索（可选）：配置了 Jev（TypeSafe）API Key 并开启时，用 Jev 理解查询意图并对候选结果重排序

系统设计从第一天就为阶段 B 预留：OCR 文本列、搜索索引、异步富化任务队列、标签列。

## 2. 调研结论

### 2.1 Paste 本身

本机装了 Paste 2.5.8（2019 年的旧版，当前是 5.x）。只做了结构层面的观察（应用包、框架、数据库表结构、偏好键名），没有反编译代码。

**技术栈**：Swift + AppKit + RxSwift，CoreData（SQLite）存储，CloudKit 同步，`MASShortcut` 全局快捷键，`LSUIElement=true`（无 Dock 图标）。

**数据模型**（CoreData 实体，值得借鉴）：

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `Snippet`（父类） | `checksum`、`title`、`timestamp`、`createdAt`、`textLength`、`totalSize`、`numberOfFiles`、`imageSize`、`preview/preview1/preview2`、`icon`、`sourceApplication`、`device`、`displayOrderInPinboard` | 子类：`TextSnippet` / `LinkSnippet` / `ImageSnippet` / `FileSnippet` / `ColorSnippet` |
| `SnippetData` | `pasteboardItems`（BLOB） | **原始剪贴板数据单独一张表**，列表只查 Snippet，不加载大数据 |
| `SnippetList` | `name`、`color`、`capacity`、`displayOrder` | 子类：`PasteboardHistory`（历史）和 `Pinboard`（收藏夹），一个条目可属于多个列表 |
| `Application` | `bundleIdentifier`、`name`、`icon`、`color` | **应用主色预先算好存库**，卡片头部配色用 |
| `Device` | `identifier`、`name`、`type` | 多设备来源 |

**二进制中能看到的剪贴板类型处理**：`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType`、`de.petermaurer.TransientPasteboardType`（旧式临时类型）、`com.apple.is-remote-clipboard`（通用剪贴板）、`com.microsoft.Link-Source` / `ObjectLink`（Office 特殊类型）、自有类型 `com.wiheads.paste.snippet`（标记自己写回的内容）。设置项里有 `ignoredApplications`、`ignoreConfidentialContent`、`ignoreAutogeneratedContent`、`kPSTPreferencesIgnoredPasteboardTypes`、`plainTextMode`。

**当前版交互**（来自官方帮助文档）：

- 屏幕底部横条，出现在当前活动的显示器上；可拖动上边缘调高度，调小时进入紧凑模式
- 时间线从新到旧，卡片显示内容预览、来源应用、时间
- 快捷键全表见 §5.4
- 搜索覆盖标题、内容、元数据，**并且能搜图片里的文字（OCR）**；筛选维度：类型、来源应用、设备、时间范围，筛选项以"内联标签"的形式出现在搜索框里
- Space 打开 Quick Look；链接用内置浏览器预览
- 没有辅助功能权限时，回车 / 双击退化为"只复制到剪贴板"
- 保留期：1 天 / 1 周 / 1 月（默认）/ 1 年 / 永久；收藏的不受保留期影响
- 颜色识别规则：单独复制的 6 位十六进制，带 `#` 或含 A–F 字母才算颜色；纯数字 `235442` 当文本（避免验证码被识别成色块）
- Paste Stack：`⇧⌘C` 开启，之后复制的内容按顺序进栈，每按一次 `⌘V` 粘贴下一个

### 2.4 Jev（TypeSafe）能力边界

来源：[docs.typesafe.ai](https://docs.typesafe.ai/introduction)

- **是什么**：结构化判断模型。输入"状态"（文本 / JSON）和一组带类型的问题，返回机器可读的答案。三种问题：
  - `choice`：从最多 255 个选项里选一个，返回每个选项的概率和置信度
  - `score`：按 2–10 个等级打分
  - `noul`：是 / 否题，返回"是"的概率
- **接口**：`POST https://api.typesafe.ai/v1/systemone`，`Authorization: Bearer <key>`，模型 `jev-latest`（当前是 `jev-1.13.0`）。JS SDK：`@typesafe-ai/sdk`（Node ≥ 20，自带重试）
- **限制**：
  - **只收文本**，图片必须先转文字，所以 OCR 是 AI 搜索的前置条件
  - 单次请求 64k tokens，其中"状态 + 最长问题"不超过 32k
  - 中文能处理，但效果不如英文，需要用真实数据测
  - **不擅长日期比较和数字运算**，所以时间范围必须由我们的代码算，不能交给 Jev
  - 无关内容越多准确率越低，所以候选要先在本地筛过
  - 不会把状态当作恶意内容处理，剪贴板内容里的"指令"可能影响排序（影响仅限排序，可接受）
- **价格**：输入 $42 / 10 亿 tokens，输出免费。一次搜索发 100 个候选 × 150 tokens ≈ 1.5 万 tokens ≈ **$0.0006**
- **限流**：1200 次 / 分钟
- **数据**：官方声明不用客户请求训练

**结论：Jev 不是向量检索，不能从全量历史里"召回"内容**。所以 AI 搜索 = 本地召回候选 + Jev 理解查询 + Jev 重排序。详见 §7。

## 3. 现状问题（`lib/clipboard/service.ts`）

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | 分类时图片优先于文件 | **Finder 复制文件会带一张文件图标 TIFF，被误判成图片** |
| 2 | 哈希覆盖所有原始类型，包括 `dyn.*`、Chromium `source-rfh-token`、WebKit 自定义数据等每次都会变的类型 | 同一段文字从 Chrome 复制两次会产生两条记录，去重失效 |
| 3 | 只过滤了 `Concealed` / `AutoGenerated`，漏了 `TransientType` 和旧式 `de.petermaurer.TransientPasteboardType` | 部分密码管理器 / 工具的临时内容被记录 |
| 4 | 原始数据以 base64 放进 JSON 文本列，图片 PNG 又单独存一份 BLOB | 数据库膨胀约 2.3 倍；单条上限 10MB 被 base64 放大后更早触顶 |
| 5 | 读取快照后又调用 `clipboard.readImage()` / `readText()` 二次读取 | 两次读取之间剪贴板可能已经变了，数据不一致 |
| 6 | 所有读写在主进程同步执行（`DatabaseSync`） | LIKE 全表扫描、清理、VACUUM 会卡住主进程，影响所有窗口 |
| 7 | 列表接口把缩略图转成 base64 data URL 经 IPC 传输 | 列表加载慢、内存高 |
| 8 | 写回防回环靠哈希 + 1.8 秒定时器 | 系统有时不产生变更事件，指纹残留期间用户真实的同内容复制会被吞 |
| 9 | 粘贴流程：激活目标应用 → 主线程 `sleep 140ms` → 发 `⌘V` | 慢、偶发粘错窗口；原生调用在主线程阻塞 |
| 10 | `⌘V` 用固定键码 `kVK_ANSI_V` | Dvorak 等键盘布局下粘贴失效 |
| 11 | 数量上限写死 240 条、保留 90 天 | 与 Paste 的"无限历史 + 可选保留期"差距大 |
| 12 | 搜索是 `LIKE %q%`，无排序、无高亮、无 OCR | 找不到图片里的字，结果只按时间排 |
| 13 | UI 嵌在主搜索窗口的 `/clip` 面板里 | 与 Paste 的底部卡片条完全不同 |

结论：**数据层、采集层、UI 全部重写**，只保留原生桥里已验证的能力（`changeCount`、快照读写、前台应用信息、OCR、应用图标）并加以扩展。

## 5. 阶段 A：复刻 Paste

### 5.1 采集流水线

```
每 250ms: 原生 changeCount 变了?
  └─ 否 → 结束
  └─ 是 → 原生读取（类型白名单，单次拷贝，返回标记位）
        ├─ 带自有标记 popMind 写回?          → 只更新该条目的"最近使用时间"，不新建
        ├─ 划词取词兜底（模拟 ⌘C）进行中?     → 跳过
        ├─ 暂停中 / 前台应用在忽略列表?        → 跳过
        ├─ 含 Concealed / Transient / AutoGenerated? → 跳过
        ├─ 命中密钥正则 / 用户自定义正则?      → 跳过
        ├─ 超过单条大小上限?                   → 跳过并记日志
        └─ 规范化 → 分类 → 去重指纹
              ├─ 指纹已存在 → 置顶、copy_count+1、更新来源应用；有更丰富的表示则补齐
              └─ 新条目 → 大数据写文件仓库 → 入库 → 推送"列表更新"事件 → 投递富化任务
```

要点：

1. **轮询间隔 250ms**。macOS 没有剪贴板变更通知，所有同类工具都是轮询 `changeCount`（Maccy 默认 500ms，EcoPaste 调到 120ms）。读取 `changeCount` 开销可以忽略。
2. **一次读取，全部来自同一份快照**。不再二次调用 Electron 的 `clipboard.readImage()`。
3. **类型白名单**（只读取这些，其余不碰，避免触发其他应用延迟生成大数据）：
   - 文本：`public.utf8-plain-text`、`public.utf16-plain-text`、`public.html`、`public.rtf`、`com.apple.flat-rtfd`
   - 链接：`public.url`、`public.url-name`
   - 图片：`public.png`、`public.tiff`、`public.jpeg`、`public.heic`
   - 文件：`public.file-url`（多个文件时每个剪贴板条目一个）
   - 元信息：`org.nspasteboard.source`、`com.apple.is-remote-clipboard`、自有标记
4. **易变类型不参与指纹**：`dyn.*`、`org.chromium.source-url`、`org.chromium.internal.source-rfh-token`、`org.chromium.web-custom-data`、`com.apple.WebKit.custom-pasteboard-data`、`com.apple.linkpresentation.metadata`、`com.microsoft.ole.source.*`。
5. **指纹按"语义内容"计算**，不按原始字节：
   - 文本：规范化后的纯文本（统一换行，去掉首尾空白）
   - 图片：解码后的 PNG 字节哈希
   - 文件：排序后的路径列表
   - 颜色 / 链接：规范化后的值
   - 富文本与同内容纯文本视为同一条，富文本表示补进已有条目
6. **来源应用**：优先读 `org.nspasteboard.source`（有些应用会写），否则用检测时刻的前台应用。
7. **大小上限**：默认单条 20MB（可设置），超限跳过并记日志。

### 5.2 分类规则（顺序很重要）

1. 有 `public.file-url` → **文件**（先于图片判断，修复 Finder 图标误判）
2. 有图片类型 → **图片**
3. 纯文本 trim 后符合颜色规则 → **颜色**。规则：`#` 开头的 3/4/6/8 位十六进制；或不带 `#` 的 6 位十六进制且至少含一个 A–F 字母；或 `rgb()` / `rgba()` / `hsl()` / `hsla()`。纯数字不算
4. 整段是单个 `http(s)://` 链接，或有 `public.url` → **链接**
5. 其余 → **文本**；有 HTML / RTF 表示时标记 `is_rich = 1`
6. 纯文本为空白但有 HTML / RTF（例如从网页复制图片时带的 HTML）→ 以富文本里的纯文本为准；仍为空则丢弃

子类型（`sub_kind`，用于筛选和卡片图标）：`email`、`phone`、`path`、`code`、`json`、`markdown` 等，由 `local-tags.ts` 统一产出。

### 5.3 存储设计

**数据库**：`userData/clipboard/clipboard.sqlite`，WAL 模式，**在 worker 线程里运行**，主进程通过消息调用，避免阻塞。

**文件仓库**：`userData/clipboard/blobs/<哈希前 2 位>/<sha256>.<扩展名>`

- 图片原图、超过 256KB 的单个表示都存文件；小数据直接存库
- 缩略图 `thumbs/<hash[..2]>/<sha256>@<尺寸>.webp`，**第一次显示时才生成**，不在采集路径上
- 渲染层通过自定义协议 `popmind-clip://thumb/<itemId>`、`popmind-clip://blob/<itemId>` 加载，不再经 IPC 传 base64

```sql
-- 应用（来源）
CREATE TABLE apps (
  bundle_id    TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  icon_path    TEXT,
  color        TEXT,              -- 图标主色，卡片头部用（参考 Paste 的 Application.color）
  updated_at   INTEGER NOT NULL
);

-- 条目（列表只查这张表）
CREATE TABLE clip_items (
  id              TEXT PRIMARY KEY,
  kind            TEXT NOT NULL,          -- text | link | image | file | color
  sub_kind        TEXT,                   -- email | phone | path | code | json ...
  is_rich         INTEGER NOT NULL DEFAULT 0,
  fingerprint     TEXT NOT NULL UNIQUE,   -- 语义去重指纹
  custom_title    TEXT,                   -- 用户重命名
  preview_text    TEXT NOT NULL,          -- 卡片摘要（截断）
  plain_text      TEXT,                   -- 完整纯文本：检索、纯文本粘贴
  url             TEXT,
  color_value     TEXT,
  file_count      INTEGER NOT NULL DEFAULT 0,
  image_width     INTEGER,
```

### 5.4 面板窗口与交互

**窗口**（`window/clipboard-panel-window.ts`）：

- 独立的 BrowserWindow：无边框、透明、`type: 'panel'`、不显示在任务栏、置顶、所有桌面和全屏应用上可见
- 启动 3 秒后**隐藏预热**（和现有设置窗口做法一致），首次按快捷键只需要播放动画
- **不激活应用**：显示时应用本身不成为活动应用，当前正在打字的应用始终保持前台。这是 Paste 手感的核心：粘贴时不需要切回目标应用，所以快且不会粘错窗口。Electron 的 `focus()` 会激活应用，因此需要原生新增 `presentPanelWithoutActivation(handle)`：`orderFrontRegardless` + `makeKeyWindow`

### 5.5 写回与直接粘贴

**写回**（`write/writer.ts`，原生实现）：

1. 清空剪贴板，按原来的条目边界还原全部表示
2. 多个文件必须每个文件一个剪贴板条目写入，否则只能粘出第一个（Maccy 的经验）
3. **额外写入自有标记类型** `app.popmind.clipboard.writeback`，值为条目 id。采集侧看到这个标记就知道是自己写回的，只更新"最近使用时间"并置顶，不新建条目。这比现在"哈希 + 定时器"的方式可靠，也不会误吞用户真实的复制
4. 纯文本粘贴：只写纯文本；如果条目含文件路径则保留文件 URL
5. 图片额外写一个临时 PNG 文件的 URL，终端类应用（如 Ghostty）需要文件路径才能粘贴图片（Clipbara 的经验）。临时文件 1 小时后清理
6. 划词取词兜底（模拟 ⌘C 后恢复剪贴板）的恢复写入也带上标记，避免污染历史

**直接粘贴**（`write/paste-service.ts`）：

```
回车 → 写回剪贴板 → 隐藏面板（等动画结束，约 60ms，键盘焦点自然回到原应用）
     → 检查辅助功能权限、安全输入模式
     → 按当前键盘布局找到输出"v"的键码，发送 ⌘V
```

- 键码不能写死：Dvorak 等布局下 V 不在同一个位置；"Dvorak - QWERTY ⌘"这种布局按下 ⌘ 后又切回 QWERTY（Maccy #482）。用 `TISCopyCurrentKeyboardLayoutInputSource` + `UCKeyTranslate` 反查
- 事件带上"左 ⌘"设备标志位 `0x000008`，部分应用不认没有物理按键对应的 ⌘（Flycut 的经验）
- 发送期间屏蔽用户仍按着的按键，避免混入
- 事件打上自有标记，Paste Stack 和划词监听据此区分合成事件和用户按键（项目里已有 `kSimulatedKeyboardEventTag`）
- 没有辅助功能权限，或检测到安全输入模式（密码框、部分终端开启"安全键盘输入"）：退化为"只复制到剪贴板"，面板底部提示原因
- 兜底：如果面板打开时前台应用就是 popMind 自己（例如从设置窗口打开），只复制不粘贴

### 5.6 Pinboard、Paste Stack、设置

**Pinboard**：名称 + 颜色，可排序；一个条目可以在多个 Pinboard 里；拖拽卡片到标签页即可加入；Pinboard 内可手动排序。旧版"置顶"迁移为默认 Pinboard"已收藏"。

**Paste Stack**：

- `⇧⌘C` 开启后在屏幕角落显示一个小的栈窗口，之后每次复制都按顺序进栈
- 原生层全局监听用户的 `⌘V`（按键抬起时），忽略带自有标记的合成事件；每检测到一次用户粘贴，就把栈里的下一项写回剪贴板
- 栈空、用户按 Esc、或再次 `⇧⌘C` 时结束

**设置页**（沿用现有设置窗口，用 shadcn 组件）：

- 通用：快捷键、保留期、容量上限、单条大小上限、回车行为（直接粘贴 / 只复制）、总是粘贴为纯文本、抓取链接预览
- 隐私：暂停记录（15 分钟 / 1 小时 / 直到恢复）、忽略应用列表（默认包含钥匙串访问、1Password、Bitwarden 等）、忽略敏感内容、忽略临时内容、密钥检测、自定义忽略正则
- 智能搜索：图片文字识别开关、识别语言；AI 搜索开关、Jev API Key、模型、测试连接、"发送给 AI 的内容"说明
- 数据：占用空间、清空历史、导出（后续）

## 6. 阶段 B-1：基础智能搜索（本地）

### 6.1 图片 OCR

- 富化队列里处理：新图片入库后投递 `ocr` 任务，**一次只跑一个**，空闲时执行，不影响采集
- 复用原生 `recognizeTextInImageAsync(imagePath)`，因为图片已经在文件仓库里，直接传路径；确认识别语言包含 `zh-Hans`、`zh-Hant`、`en-US`，使用精确模式
- 超大图（超过 2000 万像素）先缩小；太小的图（小于 32×32）跳过
- 结果写入 `ocr_text` 并更新 `clip_search`；失败最多重试 2 次
- 启动时把历史里未识别的图片补进队列（旧数据迁移后也会补）
- Quick Look 里可以显示和复制识别出的文字

### 6.2 本地标签

`local-tags.ts` 用正则给文本和 OCR 文字打标签，标签写进检索索引。这样搜"电话""快递单号"能找到只含号码、不含这些字的条目：

- 手机号 / 电话、邮箱、网址、IP、身份证号、银行卡号、快递单号（顺丰、中通等常见格式）、金额、日期、验证码
- 代码（按符号密度和关键字判断）、JSON、Markdown、文件路径

每个标签同时存中英文关键词（如 `phone 电话 手机`）。

### 6.3 查询解析

`query-parser.ts` 把搜索框内容拆成关键词和筛选条件，筛选条件在搜索框里显示为可删除的标签（Paste 的交互）：

- 显式语法：`type:image`、`app:微信`、`in:工作`（Pinboard）
- 自动识别：以"图片 / 截图 / 链接 / 文件 / 颜色"等词开头或结尾时，提示可转为类型筛选
- 中文时间词（由代码计算时间范围，不交给 AI）：今天、昨天、前天、本周、上周、本月、上个月、最近 N 天 / 小时
- 应用名匹配：与 `apps` 表的名称比对，命中时提示可转为应用筛选

### 6.4 召回与排序

1. 查询按空白拆词。**每个词都至少 3 个字时**走 FTS5 trigram（前缀匹配表达式，词之间是"并且"）；**只要有一个词不足 3 个字**（中文两字词很常见，比如"发票"），降级为 `LIKE` 匹配（EcoPaste 的做法，trigram 索引对不足 3 个字的词永远匹配不到）
2. 两种方式都覆盖标题、正文、OCR 文字、标签、应用名、链接
3. 没有结果时，对最近 2000 条的标题做模糊匹配兜底（容错错别字，参考 Maccy 的混合模式）
4. 排序分数 = 文本相关度（bm25，标题和正文权重高于 OCR 和标签）+ 时间衰减 + 使用次数加成；Pinboard 里的条目小幅加成
5. 返回命中片段和高亮位置，卡片上高亮显示；图片命中 OCR 时卡片角标显示"文字匹配"
6. 输入时 80ms 防抖，搜索在 worker 线程执行，目标 1 万条内 50ms 以内返回

## 7. 阶段 B-2：AI 搜索（Jev，可选）

### 7.1 开启条件

同时满足才启用，否则只用本地搜索，界面上不出现 AI 相关元素：

1. 设置里打开"AI 搜索"
2. 填写 Jev API Key 并测试通过

### 7.2 流程

```
用户输入 → 本地搜索立即出结果（不等 AI）
        → 满足触发条件时（停止输入 500ms，且查询像自然语言：≥ 2 个词或 ≥ 5 个汉字；或按 ⌘↩ 强制）
             ① 意图理解（Jev，一次请求，和 ② 并行）
             ② 候选池 = 本地关键词结果前 60
                      ∪ 按已识别的筛选条件取最近 150 条（弥补关键词召回不到的情况）
                      去重后最多 200 条
             ③ 按 ① 的结果过滤候选池 → 重排序（Jev）
        → 结果区顶部出现"智能排序"分组，与本地结果合并展示；用户可一键切回按时间排序
```

**① 意图理解**：状态是用户的查询原文，一次请求问多个问题：

- `choice` 类型：`text | link | image | file | color | any`
- `choice` 时间段：`today | yesterday | this_week | last_week | this_month | last_month | any`，**Jev 只负责理解用户说的是哪个时间段，具体起止时间由代码计算**（Jev 不擅长日期比较）
- `choice` 来源应用：选项为 `apps` 表中最近使用的应用（≤ 250）+ `any`
- `noul`：用户是否在找"某一类内容"（如"所有快递单号"），是的话结果不截断

置信度低于阈值（初定 0.6）的条件不采用。

**③ 重排序**：参考官方"逐行语义查找"示例。把候选编号后拼成状态，每条截断到约 300 字：

```
C001| [文本][微信][3天前] 明天下午三点在 A 座 302 开会，记得带合同……
C002| [图片 OCR][截图][上周] 顺丰速运 运单号 SF1234567890 收件人……
…
```

一次请求两个问题：

- `choice`："哪一条最符合用户要找的：<查询>？"，选项是 `C001…C200`（描述为空，让模型读状态）。**返回的概率分布就是排序依据**
- `noul`："有没有任何一条符合？"。概率很低时提示"AI 没找到更相关的内容"

候选超过 255 条或状态超过 32k tokens 时分组并行请求，再对每组前几名做一次决赛排序。

最终分数 = Jev 概率为主，本地分数作为同分时的次序。

### 7.3 （可选增强）入库时 AI 标签

AI 搜索打开时，富化队列可以对新条目批量调用 Jev 做分类（会议 / 地址 / 订单 / 代码 / 账号信息…），结果写进 `tags`，以后本地搜索也能用。每条约 200 tokens，成本可以忽略。默认关闭，第一版不做，只预留 `ai_tags` 任务类型。

### 7.4 隐私与成本

- 敏感条目、忽略应用来源的条目、用户标记"不发送给 AI"的 Pinboard，永远不进入候选池
- 只发送截断后的文本摘要，不发送图片本身（Jev 也不接受图片）
- 设置页明确说明"开启后，搜索时会把候选内容的文字摘要发送到 TypeSafe"
- 每次调用记录 token 用量，设置页显示本月累计用量和估算费用
- 429 / 529 指数退避重试；超时 3 秒放弃 AI 结果，只保留本地结果
- 剪贴板内容可能包含"指令"类文字，最坏影响是排序不准，不会触发任何操作

### 7.5 效果验证

中文不是 Jev 的强项，上线前用真实数据做一次评估：

1. 从开发者自己的历史里挑 30 组"查询 → 期望条目"（含图片 OCR、口语化描述、错别字）
2. 比较三种方式的"第一名命中率"和"前五名命中率"：本地搜索、本地 + Jev 重排序、本地 + Jev 意图 + 重排序
3. 如果 Jev 在中文上提升不明显，保留 AI 开关但默认只用意图理解，或者把接口做成可替换（将来可以接向量检索，`loadExtension` 已验证可用）

## 10. 已确认的决定（2026-09-29）

1. **回车默认直接粘贴**（`directPaste: true`），无权限时降级为只复制
2. **主搜索里的 `/clip` 直接打开新面板**，旧的列表 + 预览面板删除
3. **链接预览抓取默认开启**（`fetchLinkPreviews: true`），可关闭
4. **AI 搜索默认手动触发**：`⌘↩` 触发（`ai.trigger: 'manual'`）；设置里可改为"停止输入 500ms 后自动触发"（`'auto'`）。§7.2 中的自动触发条件只在 `auto` 模式生效
5. **Jev 能力**按 §7.5 评估结果决定默认开启哪些
6. **Paste Stack 全局快捷键默认不绑定**（`clipboardPasteStack: ''`），全局抢占 `⇧⌘C` 会影响 Chrome DevTools、Finder 等；设置里可绑定。面板内 `⇧⌘C` 始终可用

### 11.4 各包交付内容与自测标准

**A 原生层**

- 实现 `macos-addon.ts` 里新增的全部可选方法；读取只读白名单类型，`allTypes` 不加载数据；超过 `maxBytes` 返回 `tooLarge`
- 写回：多文件按条目 `writeObjects`；在第一个条目上写 `POPMIND_PASTEBOARD_MARKER`
- 划词取词兜底恢复剪贴板时也写入标记（值 `text-picker-restore`）
- `postPasteKeystroke`：按当前键盘布局反查"v"的键码（`TISCopyCurrentKeyboardLayoutInputSource` + `UCKeyTranslate`，必要时链接 Carbon），标志位含 `0x000008`，屏蔽本地按键，事件打 `kSimulatedKeyboardEventTag`；无权限 / 安全输入返回原因
- `presentPanelWithoutActivation`：参照已有 `ConfigureBubbleWindow` 取 NSWindow，确保 `NSWindowStyleMaskNonactivatingPanel`，`orderFrontRegardless` + `makeKeyWindow`，collectionBehavior 含所有桌面和全屏辅助，层级高于 Chrome 自动填充（≥ 1000）
- `startPasteMonitor`：全局监听物理 `⌘V` 抬起，忽略带标记的合成事件
- `resolveAppPathByBundleId`、`recognizeTextInImageWithOptionsAsync`（默认 zh-Hans / zh-Hant / en-US、精确模式）
- 自测：`pnpm run build-native` 通过；用 `ELECTRON_RUN_AS_NODE=1 node_modules/.bin/electron <脚本>` 验证文本 / HTML / 多文件 / PNG 的写回再读取一致、标记可读、`tooLarge` 生效、键码反查结果（不实际发送按键）

**B 数据层**

- worker 线程里的 `node:sqlite`（WAL、外键开启），主进程侧 `clipStore` 以消息 RPC 实现 `ClipStore` 全部方法；数据库逻辑写成可以直接在测试里实例化的类（接收 `DatabaseSync`），worker 只是薄壳
- 文件仓库（§5.3）、迁移框架、旧库导入（§5.3）
- `list()` 必须调用 `searchClips(db, query, ctx)`，再把命中映射成 `ClipListItem`（带 `match`、`thumbnailUrl`、`source.iconUrl`、`pinboardIds`）；写入 / 更新 / 删除条目时同步维护 `clip_search`（title、body 截断到 `CLIP_SEARCH_BODY_MAX_CHARS`）
- 采集流水线 §5.1、分类 §5.2、隐私过滤（含 EcoPaste 式密钥正则）、语义指纹；看到标记时调用 `markUsed`（值为条目 id）或忽略（`text-picker-restore`）；变更后发 `clipboardEvents.emit('items-changed', …)`
- 富化队列：缩略图（Electron `nativeImage`，最长边 480）、OCR（`clipboardNative.recognizeText`，受 `ocr.enabled` 控制）、本地标签（调用 `computeLocalTags`）、应用元数据（图标写文件 + 主色）
- `resolveClipAsset`：thumb 缺失时现生成
- 保留期 / 容量清理、软删除与撤销、孤儿文件回收
- 自测：用 `npx tsx`（支持 tsconfig 路径）在系统 Node 22 上跑脚本：入库去重、置顶、搜索、Pinboard、软删除撤销、保留期清理、旧库导入（用一份合成的旧库）

**C 面板界面**

- 按 §5.4 实现：搜索栏（内联筛选标签、建议）、Pinboard 标签页、横向虚拟列表（每页 100 条，滚动到底加载下一页）、六类卡片、头部应用主色、`⌘` 数字角标、Quick Look 层（富文本放沙箱 iframe）、右键菜单、编辑 / 重命名对话框、删除撤销提示、底部权限 / 目标应用提示、拖动上边缘调高度
- 快捷键全表（§5.4），输入法组词期间不响应
- 入场 / 退场动画：收到 `onPanelShow` 时内容从下滑入；收到 `onPanelRequestHide` 或本地关闭时滑出后调用 `hidePanel()`
- AI 搜索：`ai.enabled` 时显示入口；`⌘↩` 触发；`trigger === 'auto'` 时自然语言查询停止输入 500ms 触发；结果以"智能排序"分组显示在最前，可切回
- 监听 `onItemsChanged` 增量刷新；图片用 `thumbnailUrl`
- 允许新增仅开发模式生效的模拟数据（`import.meta.env.DEV` 且 URL 带 `?mock`），用于在浏览器里单独预览；生产构建不得包含
- 自测：类型检查、`pnpm exec electron-vite build` 通过；用 vite 开发服务器 + `?mock` 在浏览器里截图检查布局（可用 Playwright / Chrome 工具）

- `lib/clipboard/service.ts`：初始化顺序 store → 旧库导入 → 采集 → 富化 → 保留期定时任务（启动后 1 分钟一次，之后每小时）

- 自测：类型检查、构建通过；无法 GUI 验证的部分在报告里列出需要开发者验证的步骤

**E 搜索 + AI**

- `query-parser.ts`：§6.3（显式语法、中文时间词 → `dateRange` 由代码计算、应用名识别、类型词建议）
- `keyword-search.ts`：§6.4 三级召回（全部词 ≥ 3 字走 FTS5 前缀匹配，否则 LIKE，零结果时模糊兜底），筛选（类型、应用、时间、Pinboard 范围、排除软删除），浏览模式（无关键词）按 `last_copied_at` 游标分页，Pinboard 范围按手动顺序
- `ranker.ts`：bm25 加权 + 时间衰减 + 使用次数；生成 `match`（片段 + 高亮区间）
- `local-tags.ts`：§6.2
- `ai/jev-client.ts`：`POST https://api.typesafe.ai/v1/systemone`，Bearer 鉴权，3 秒超时，429 / 529 指数退避，可取消；用 `fetch`，不新增依赖
- `ai/jev-intent.ts`、`ai/jev-rerank.ts`、`runAiSearch`：§7.2（意图置信度阈值 0.6，候选编号 `C001…`，超过 255 个或 32k tokens 分组并行 + 决赛），`testJevConnection`
- 自测：`npx tsx` 脚本 + 内存 SQLite（用 `CLIP_SCHEMA_V1` 建表、造数据）验证中英文、两字词、OCR 命中、筛选、分页、高亮；AI 部分用模拟 `fetch` 验证请求格式和结果解析

**F 设置页**

- 设置窗口新增"剪贴板"分区（§5.6）：通用、隐私（忽略应用：从 `clip-list-apps` 选择 + 手动输入 bundle id）、智能搜索（OCR 开关、AI 开关、Jev API Key、模型、触发方式、测试连接、用量）、数据（占用空间、清空历史需二次确认）
- 快捷键区新增"连续粘贴"（`clipboardPasteStack`）
- 通过 `capability.updateSettings({ clipboard: … })` 保存；风格与现有设置页一致（`settings-kit.tsx`）
- 自测：类型检查、构建通过
